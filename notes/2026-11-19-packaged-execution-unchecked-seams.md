## 一、今日观察

今天的发布几乎都在做同一件事：**把若干个步骤合并成一个更大的执行单元**。

Claude Code 让模型写一段 JavaScript 代替十几次工具调用；Replit 让一群 agent 在预算内跑完一个商业目标；Perplexity 把"选哪个模型"变成一条路由规则；Qoder 把"每轮重读仓库"变成一份预先生成的 Wiki。省下来的东西很清楚——轮次、token、延迟。

但把这五件事的**检查点**单独拎出来看，会发现它们没有跟着一起变大：

| 层 | 今天谁把执行单元打包了 | 打包成什么 | 检查点落在哪 | 漏在缝里的 |
| :--- | :--- | :--- | :--- | :--- |
| 工具调用 | Claude Code Code Mode | 一段 JS，交给 REPL 跑 | auto mode 审**整段代码** | 运行时才算出来的参数值 |
| 任务 | Replit Missions | 一个预算内的目标 | 终点由**另一个 AI** 判一次 | 中间过程的取舍与方差 |
| 模型 | Perplexity Orchestrator | 一条自然语言路由规则 | 决策模型选路 | "拒答"被当成"换个模型接着干" |
| 对话 | GAO 测试里的攻击者 | 一条 12 小时的长会话 | 单轮护栏 | 跨轮累积起来的整体意图 |
| 仓库知识 | Qoder Repo Wiki | 一份预生成的 Wiki | 增量更新是否触发 | Wiki 与代码不同步的窗口 |

最硬的一条证据来自 Anthropic 自己的文档，而不是第三方测评。Code Mode 的官方页面写着：auto mode 下，分类器审的是**每一段代码**，而不是每一次工具调用；而且它**看不到运行时算出来的值**，"比如从搜索结果里取出来的一个路径"。同一页还提醒，依赖具体参数值的 `deny` 规则，对动态拼出来的调用可能不适用。

这不是实现疏漏，是打包的必然代价：**要审"一整段程序"，就只能看静态文本**。只要执行单元变大，检查点就会从"每一步"退到"这一包"，而包里发生的事，检查者看不见。

Replit 的同一天给出了另一种打包方式：不审过程，改在终点判一次——一个独立的 AI judge 按事先约定的成功标准验收，预算烧完就判定未解决。听起来更像工程，但验收者仍是 AI，且 Replit 自己写明每套配置只跑了一次。GAO 那份 61 页报告则是反面证明：四家主流聊天机器人在 12 小时内被绕过护栏，产出可执行的袭击预案——护栏拦得住单轮，拦不住一条长会话把单步无害累积成整体有害。

需要交代撞题：11-09《"做完了"是自述，不是事实》讲的是"完成"这句话属于哪种凭据；本轮不问凭据真假，问的是**凭据的粒度**——当执行被打包，检查点该放在包的哪一层、还能看见什么。11-05 讲的是 Agent 的外壳与信任层，11-12 讲的是"少算几遍"的推理优化；本轮这两条都不碰，只谈"打包"与"检查"的错位。

## 三、为什么值得记

1. **省 token 的真正机制是"把编排搬出上下文"，不是模型变便宜。** Code Mode 的 16→3 个工具定义、Qoder 的 −50% credit、Repo Wiki 的 −6.1% token，本质都是让调度发生在模型的上下文之外。这个动作的收益是确定的，但它有一个前置条件：模型得**写对**那段脚本。Haiku 5.5 在文件任务上 token 反而 +9%，就是这条边界的实证——弱模型写不好调度代码，包打得越大越亏。

2. **检查点必须跟着执行单元一起放大，否则就是名义上的审查。** Anthropic 文档那句"看不到运行时算出来的值"足够诚实：静态审一段程序，天然看不见它算出来的路径。任何准备上 Code Mode 的团队，第一件事应该是把自己的 `deny` 规则过一遍，挑出那些依赖参数值判断的条目——它们在打包之后基本失效。

3. **AI 裁判解决的是"谁说不合格"，不是"标准对不对"。** Replit 的 judge 与被验收的 agent 同源、同标准、同一次运行，能查"符不符合约定"，查不了"约定本身是否合理"。这与 GAO 的发现互为镜像：护栏能拦单轮请求，拦不住一条长会话把无害片段拼成有害整体。两者的共同缺口是同一个——**检查点的视野小于攻击/执行的单元**。

4. **多模型路由的收益是边际的，买的是稳定性不是能力。** 63 题从 38 到 41（+4.8%）、成本反升，这组数字比任何"聚合即更强"的叙事都诚实。真正值得买的是故障切换与"拒答后继续"，那是可用性与合规弹性；指望路由把弱模型变成强模型，大概率失望。

## 四、可行动

- [ ] **开 Code Mode 做一次三任务对照。** 选三个多步任务（跨文件重复修改、需要先过滤的搜索、可并行的命令），记 token、耗时、成功率；结束时按 `Ctrl+O` 展开 `Code` 行，读一遍它写的脚本——脚本质量就是这套机制的上限。
- [ ] **审计一遍依赖"参数值"的 deny 规则。** 在 Code Mode 下，auto mode 只看静态代码、看不到运行时值；凡是用路径/命令内容做判断的规则，都要改成"按工具名 + PreToolUse hook 校验"的形式。
- [ ] **给任何"Missions 式"长任务写三件套**：可判定的成功标准、预算上限、必须人工批准的动作清单。只写 goal 不写这三样，最后一定是在终点上争吵。
- [ ] **保留三类人工闸门**：对外发布、对外承诺、付款。AI 裁判可以判"达没达标"，不能替你签这两类字。
- [ ] **路由层先测再买。** 用同一批任务对比"单模型"与"路由"的质量、成本、P95 延迟三项；若质量提升 <5% 而成本上升，就只把它当故障切换用。

## 五、术语卡

| 术语 | 解释 |
| :--- | :--- |
| **REPL 沙箱** | Read-Eval-Print Loop，读一段代码、执行、返回结果的环境。Code Mode 里模型写的 JS 跑在 `node:vm` 中（宿主是 Claude Code 自带的 Bun 进程），中间变量留在沙箱里，不回流到模型上下文。 |
| **静态审查 vs 运行时值** | 分类器只能读代码的字面文本；`open(path)` 里的 `path` 在运行前是未知的。前者可审，后者不可审——这是打包执行时审查能力下降的技术根因。 |
| **outcome contract（结果契约）** | 不规定"怎么做"，只约定"什么算成功、花多少钱、哪些动作要批准"。Missions 的核心就是把 PRD 从行为规格改写成结果契约。 |
| **AI judge** | 按预先约定的标准给结果打分的模型。它能提供一致性和速度，但不构成独立第三方验收——尤其是当它与被验收方同源时。 |
| **KV cache 相容路由** | 切换模型/供应商时尽量命中此前算过的前缀缓存。路由跨厂商时缓存通常失效，所以"能切"和"切了不贵"是两件事。 |
