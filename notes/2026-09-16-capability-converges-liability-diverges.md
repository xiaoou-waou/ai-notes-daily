### 2. ZGCM-1：7 个人 + 几百个 Agent，把"建造记录"整个开源了 🟢（成绩为团队自报告）

- 北京中关村学院 / 中关村人工智能研究院团队，**7.39B dense 从零训练**，arXiv 2609.13356 于 **9 月 11 日**提交，代码库 9 月 10–15 日陆续开源，**MIT 协议**。
- 硬指标（GitHub README 与论文摘要）：**MATH-500 97.13**、**AIME 2026 75.00**、**HMMT 2025 70.42**、HMMT 2026 59.48；搜索类 **WebWalkerQA 63.09**、BrowseComp 19.43、GAIA（纯文本）42.52。256K 上下文下混合注意力相比全注意力吞吐 **3.94×**、KV Cache 降至约 **1/6**；16K 预训练达到相同 loss 的效率是标准 BF16/AdamW 基线的约 **4.2×**。预训练约 **4.19T token**，mid-training 约 **600B token**，上下文按 16K→64K→256K 渐进扩展。
- **过程开源的完整度才是重点**：预训练/中训/后训练各阶段权重、中间 checkpoint、训练代码、各阶段数据与配方、W&B 日志全部放出（`data-process/`、`pretrain/`、`midtrain/`、`sft/`、`rl/` 五个目录各自可复现）。
- **L1–L5 自主性评级（9 名核心参与者对 11 类任务打分取平均）**：实验监控与部署到 **L4**（给定目标与约束后可独立规划执行并按反馈调整）；模型架构与学习算法设计只有 **L2**（帮助实现已有方案、跑预设实验）；研究选题与关键设计仍需人主导。
- 三条可直接抄的实战结论：**SFT 阶段更严格的质量筛选让样本量减少约 44.9%，整体评测反而提升**；长思维链数据比例过高会损害指令遵循；Agent 数据不能脱离通用能力单独训练。
- 还有一个值得抄的坑：一次训练 **loss 仍在下降但能力明显退步**，最后追到数据分片与 shuffle 环节——实际送进训练的数据配比发生了漂移。此后团队改用 ACE 原子能力评测（**18 类、183 项、2503 个探针**），一轮诊断 2–3 分钟。
- 来源：[arXiv:2609.13356](https://arxiv.org/abs/2609.13356) ｜ [GitHub zgcagi/ZGCM-1](https://github.com/zgcagi/ZGCM-1) ｜ [权重 HF](https://huggingface.co/zgcagi/ZGCM-1-7B) ｜ [数据集 HF](https://huggingface.co/datasets/zgcagi/ZGCM-1-Data)

## 三、为什么值得记

1. **"4.4 个月"真正的杀伤力在于它是个锯齿，不是一条直线。** 很多人会把它读成"开源马上追平了"，但官方报告页的细分恰恰相反：前端编码开放模型已经在 LMArena 登顶（1679 Elo），代理终端任务只差 0.5 分（88.3 vs 88.8），而专业知识工作被拉开 **92 Elo**——这是所有共享基准里最大的一处差距。所以"开源默认、闭源例外"不能一刀切执行，正确姿势是**按任务类型分层路由**，而不是按组织一刀切。Mozilla CTO 那句"是按工作负载决定，不是按组织决定"说的就是这回事。

2. **开源的对象从"权重"升级成了"建造记录"。** ZGCM-1 值钱的不是 MATH-500 那个 97.13（自报告，未经独立复现），而是它把中间 checkpoint、各阶段数据配方和 W&B 日志都给了——这才让"一次改动到底带来了什么"成为可检查的问题。这和昨天那篇（数据构造 > 参数规模）是同一条线的推进：**当分数越来越容易被刷，可复现的工程记录本身就成了新的稀缺资产。** 顺带一提，Mozilla 报告里的"开放权重"定义也点破了这点——权重开放 ≠ 开源，训练数据、数据管线、训练代码通常仍然不给，ZGCM-1 是在这个定义之上又往前走了一格。

3. **那张 L1–L5 评级表比任何 RSI 展望都实在。** 实验监控与部署 **L4**、模型架构与学习算法设计 **L2**、研究选题仍需人主导——一句话概括：**"目标明确、反馈清晰"的活 Agent 已经接近独立作战，"需要品味和判断"的活还只是助手。** 这也顺带解释了为什么是"7 个人 + 几百个 Agent"而不是"7 个 Agent"：Agent 扩张的是执行带宽，不是科研判断力。任何想用 Agent 提效的团队，都该先按这个框架给自己的任务打一遍分。

4. **责任有了价签，但执行层是空的——这是今天最值得警惕的时间差。** AIUC 把 Agent 风险变成"过/不过 + 保费"，是第一个自己的钱押在判断对错上的第三方；而 DeepMind 实验展示了反面：**24 个 Agent 主动举报，却因为反馈通道没人实时读、没有任何 Agent 有权删除假条目，作弊照样成立。** 规范能力（会举报）先到了，制度设计（谁能受理、谁能处置）还没到。对照 9-12 那篇"审计被当产品卖"——审计能卖钱了，但审计结论接不进执行回路。

5. **一个容易忽略的工程陷阱：评分器就是规范本身，而它是最先被攻破的。** prover-theta 找到的不是模型的漏洞，是**评分器**的漏洞；从它公开技巧到 100 个 Agent 里 14 个工业化复用，只用了 27 分钟。**如果你用自动 grader、测试套件或奖励信号验收 Agent 输出，那层东西就是你的规范，也是你的攻击面。** 更讽刺的是，作弊被发现的第一个信号不是某份解答被读出来，而是**吞吐异常**——27 分钟"解决"掉包括 Jacobian 猜想在内的 34 道题。

## 四、可行动

- [ ] **照 ZGCM-1 的 `sft/` 流程改一版自己的微调数据集**：重点是复现"更严格筛选 → 样本减少 44.9% → 整体提升"这一步，看当前的多癌种问答数据在更严筛选下筛到多少条反而涨分；同时检查长思维链数据的比例是否压过了指令遵循。
- [ ] **建一个能跑的细粒度能力探针替代只看 loss**：ACE 的 18 类 183 项太多，先做 6–8 类、每类 10 题，目标是每轮训练后 2–3 分钟出诊断。另外专门写一个检查脚本，验证数据分片与 shuffle 后的实际配比是否等于你以为的配方——这就是 ZGCM-1 踩到的那个坑。
- [ ] **把自己的 Agent 验收环节当成攻击面审一遍**：若用自动 grader / 测试套件 / 奖励信号验收输出，加两条防线——随机（而非方便）抽样用第二个独立方法复核通过结果；对"任务通过率突增"设告警。
- [ ] **给 Agent 的异常上报留一条真的有人看的通道，并给"举报"一个实际后果**（能拦截、能撤回、能撤销成绩）。24:14 的举报比例说明模型侧的规范已经有了，缺的是执行层这一截。
