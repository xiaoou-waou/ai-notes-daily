## 三、为什么值得记

1. **成本战的主战场换了。** 输入输出单价几乎冻结，降的是缓存。这意味着厂商在告诉你：**重复上下文很便宜，新鲜的、没命中的 token 才贵**。Agent 架构设计（什么放前缀、什么进上下文、何时重建会话）第一次有了明确的金钱刻度。
2. **"性价比榜"成为独立于"能力榜"的竞技场。** Qwen3.8-Max 在能力榜夺魁的同时，价格只有第二名的 1/4——能力和价格不再是简单的正相关。选型时单看 SOTA 分数会系统性高估成本。
3. **硬件门槛被量化技术砸开。** 1.5TB → 214GB 不是"小模型也能用"的妥协，而是几乎不掉点的压缩。个人/小团队本地跑 trillion 级模型的窗口正在打开（虽然 1.02 token/s 目前还只适合批处理场景）。
4. **端侧百万上下文出现。** 星火 X2.5 把 100 万上下文塞进 1.7B/4B 端侧模型，配合 0.85 秒响应——端侧 Agent 的"记得住"第一次有了工程基础。

## 五、术语卡

| 术语 | 一句话解释 |
| --- | --- |
| **缓存读取（Cache Read）** | 模型重复处理已缓存的输入内容时的计费项，单价远低于正常输入。Agent 反复重放长上下文时，这是主要成本项。 |
| **帕累托前沿（Pareto Frontier）** | 在"能力 vs 价格"平面上，不存在其他模型能在两项上都更优的那些点。落在前沿上 = 没有白白多花钱。 |
| **稀疏三值量化** | 把权重压缩到接近每参数 1–2 bit 的技术。混元的 Sherry 方案做到平均 1.25 bit。 |
| **混合精度（Mixed Precision）** | 按层敏感度分配不同量化精度——敏感层用高精度，冗余层用低精度，在体积和能力之间取最优折中。 |
| **Harness** | Agent 中执行层的统称：工具调用、文件读写、代码执行、测试验证、上下文管理。区别于负责推理的 Model 本身。 |
