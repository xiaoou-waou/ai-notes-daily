## 一、今日观察

11 月 11 日到 12 日，五份发布材料里都出现了同一个词：更快。但把它们的做法摊开，会发现这是两件完全不同的事——**少做无用功**，和**把有用的功做得更快**。

前五行改的是**"要算几遍"**，最后一行改的是**"每遍算得多快"**。

这就是今天值得记的地方：**"快"被拆成了两笔账，而产业几乎全部力气都压在"少算几遍"这一侧。** 原因不难找——agent 把遍数放大了。一次 agent 任务动辄几十次模型调用，Gemini 把 1000 个判断塞进一次前向、BotPsy 把思考 token 砍掉三分之二，省下的不是 5%，而是乘以调用次数之后的那部分。

而"每遍算得更快"这一侧，今天只有一家在卖，且能卖两倍价。这不是巧合：**少算几遍是工程问题，可以靠训练、蒸馏、接口设计解决；算得更快是物理问题，得等芯片和内核。** 前者今天批量产品化，后者仍然是稀缺品。

### 1. Gemini Decision 1：把"判断"从生成里摘出来，输入只计一次费 🟢

## 三、为什么值得记

**1. 这一轮提速的来源，几乎全是"取消重复"，而重复是 agent 自己造出来的。** 单轮问答里，思考 token 省三分之二只省三分之二；但 agent 一次任务几十次调用，省的是乘积。Gemini 那条更极端——**输入按次计费，问题数不计费**，等于把"多问几个"的边际成本打成零。这不是模型变强，是计费结构变了，而计费结构会反过来改变你怎么设计系统：以前你会想办法把 20 个判断合并成 3 次调用省 token，现在这个问题不存在了。

**2. 每一笔"省"，代价都写在同一份材料里，只是不写在标题上。** BotPsy 官方自己说知识仍随规模增长、该查工具别凭记忆；ERNIE 5.5 Flash 官方自己说这是"训练不充分的中间版本"；H3-Image 的速度数字到现在没有第三方计时。**读到"更快"的发布，第一件事是在同一页找它放弃了什么**——今天这三条都老实写了，只是写在小节深处。

**3. 判断被单独做成接口，最大的收益不是准，是可校准。** Decision 1 每个答案都带 0–1 置信度，这意味着"我不确定"第一次成为可编程信号：低于阈值转人工、高于阈值直接放行。比起"生成一段话再解析出是/否"，它同时干掉了三样东西——输出 token 成本、JSON 解析失败、以及"模型写了长篇但没给结论"。（9-22 写过同一类东西：社区级的小决策模型。今天的不同有两点——它变成大厂的一等 API，且计费从"按输出"改成"输入只算一次"。）

**4. 同一份预算被两个人用，账单就会互相挤。** Qwen4-Max 的 393,216 是**思考与回答共享**的额度：想得多，答得就短。这和"默认开思考"叠在一起，意味着默认配置下你既付了思考的钱，又可能被截断回答。BotPsy 那边是镜像案例——它的基座模型在同一个任务上绕圈子重试，直到耗尽步数。**同一个模型，配置不同，账单差几倍**；而你今天付的钱，很大一部分不是你在 prompt 里选的。

## 五、术语卡

| 术语 | 解释 |
|---|---|
| **单次前向打分（single forward pass scoring）** | 不做逐 token 解码，一次性算出每个候选选项的概率。省掉的是整个生成过程，不是把生成做快 |
| **无分类器引导（CFG）** | 扩散模型里用"有条件/无条件"两次预测差值来强化提示词作用的技巧。去掉它能省一半前向，代价是可控性下降，需要靠蒸馏补回来 |
| **稀疏激活（MoE）** | 模型总参数很大，但每个 token 只路由到一小部分专家。ERNIE 5.5 Flash 是 280B 总参、14B 激活，算力按激活部分计 |
| **思考 token（reasoning tokens）** | 模型在给出最终答案前写给自己看的中间推理。它和答案共享输出预算，也共享账单——BotPsy 的核心成绩就是把这块压掉 68% |
| **校准（calibration）** | 模型说"我有 80% 把握"时，这类问题里是否真有约 80% 答对。决策类接口能不能用来分流人工，取决于这个而不是准确率 |
