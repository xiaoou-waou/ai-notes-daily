## 一、今日观察

这一周的技术新闻看起来都在讲"小"——小模型、小机器、小集群。但把它们并排放，会发现讲的其实是同一件老事：**装不下**。

| 方案 | 今天谁给的样本 | 省掉的是什么 | 没省掉的是什么 |
| :--- | :--- | :--- | :--- |
| 稀疏激活 | 腾讯 Hy4：770B 总参 / 49B 激活，256 专家选 8 | 每 token 的乘加量（约 1/16 的专家参与计算） | 权重总量——FP8 也得把 770B 一字节一字节装进去 |
| 循环深度 | Inkling 2 Mini：26.4B 总参 / 3.4B 激活，24 层里 12 层跑 3 遍 | 用"多跑几遍"换推理深度，参数不增 | 延迟——同一批权重每个 token 走三趟 |
| 低比特 | Qwen3-235B-A22B Q4_K_M，三台 128GB 迷你机 | 每个参数的字节数（4 位约 0.5 字节） | 互联——每个 token 都要跨机交换激活值 |
| 拼机器 | 微软 RDMA over USB4 | 专用 RDMA 网卡与交换机，以及"一台机器"这个前提 | 失败恢复——官方写明传输层不重传 |

**稀疏化是这一列里最容易被误读的一项。** Hy4 每个 token 只激活 490 亿参数，听起来像"用 490 亿的机器跑 7700 亿的模型"。但被省掉的是 FLOPs，不是 HBM：7700 亿个权重一个不少地要占地方。这正是"权重开源了、你也能下载、但你跑不动"的技术原因，也是腾讯同时给出 FP8 版、base 版和 vLLM/SGLang 部署方案的原因——那套东西是写给有机架的人的，不是写给笔记本的。

微软的三台迷你机，就是这条线的另一头。235B 参数按 4 位存，光权重就约 118GB（按 0.5 字节/参数估算），而单机统一内存只有 128GB——剩下的余量还要装 KV cache 和上下文。所以"三台"不是在炫技，是把一个容量问题改写成拓扑问题。

拓扑有硬约束，而且写得很清楚：**N 台机器，每台要 N-1 个 USB4 口，必须两两直连，菊花链会让性能明显下降。** 三台 = 每台 2 个口 + 3 根线；四台 = 每台 3 个口 + 6 根线。这条约束把"你的两台笔记本"基本排除在外，剩下的现实形态是"桌边一台迷你机机架"。热闹的是"手机电脑都能跑大模型"，能用的是"你愿意为它买三台同款机器"。

最值钱的一句官方话藏在限制条款里：传输层不做重试，连接断了由应用自己重建。**拼出来的容量是免费的，拼出来的可用性不是。**

同一周资本市场在给"集中"重新定价：11 月 20 日纳指跌 5.28%、费城半导体指数跌 10.73%、英伟达单日跌 14.1%，市值较 10 月峰值蒸发约 2.65 万亿美元；路透报道 SEC 执法部门正在审查其可能的会计问题，关注点之一是地理收入披露口径的调整（调查不等于违规）。这不构成因果，只提供一个背景：当"集中"变贵的时候，"分散"会被更多人认真算一遍账——而这份账的最后一行，通常不是"省多少钱"，是"出事时谁来兜底"。

### 1. 🟢 微软把"一台机器"扩展到桌边：RDMA over USB4 开发者预览

11 月 19 日发布于 Microsoft USB Blog。做法不是新造一个 API，而是把 Windows 已有的 **NetworkDirect**（数据中心 RDMA 网卡用的那套接口）接到 USB4 上：新的 provider 在 USB4 host router 的 DMA 环上实现 RDMA，应用层照旧写 NetworkDirect，推理框架不需要知道底下是 USB4。官方说法是"不用买 RDMA 网卡、不用配交换机、不用装第三方驱动"。

关键数据（均为微软与合作方自测）：两机之间小消息**往返延迟约 28–50 μs**，约为同一 USB4 链路上以太网（UDP）的**四分之一**；40Gbps 与 80Gbps 的延迟相同，后者带宽翻倍。AMD 侧三台 Ryzen AI Max+ 395、各 **128GB 统一内存**、40Gbps 全互联，跑 **Qwen3-235B-A22B（4 位量化 Q4_K_M）约 18.5 tok/s**，AMD 自测解码 **21.98 tok/s**、提示词处理 **117.98 tok/s**（1,600 上下文 / 生成 2,048）。Intel 侧三台与四台 Core Ultra Series 3、各 64GB、Thunderbolt 4 全互联，跑 **GPT-OSS-120B** 分别为 **49.4** 与 **54.2 tok/s**（1K 上下文）；微软注明该模型装不进单台 64GB 机器。

限制条款比性能更值得读：N 台机器每台需要 **N-1 个 USB4 口**并两两直连（三台每台 2 口），**菊花链会显著掉性能**；预览默认关闭，要开注册表并启用测试签名——**测试签名要求关掉 Secure Boot**，因此官方建议用专门的测试机；**传输层不重试**，连接断开需应用自行重建。开源部分已放出：NetworkDirect provider 与一个把 RPC 后端从 TCP 换到 NetworkDirect 的 llama.cpp 分支；所需 Insider build 尚未发布。

## 三、为什么值得记

1. **"激活参数"是吞吐指标，不是部署指标。** 7700 亿总参、490 亿激活，意味着单 token 的计算量接近一个 490 亿的稠密模型，但显存需求仍按 7700 亿算。厂商发布会爱讲前者（它决定速度与单价），你的采购单只认后者（它决定你能不能开机）。把这两个数并列写进评估表，能省掉一次白买的机器。

2. **拼机的门槛不是带宽，是拓扑和签名。** 每台 N-1 个口、必须全互联、菊花链掉性能——这三条把方案从"两台电脑一根线"推到"三台同款迷你机 + 六根线 + 专用测试机"。而"要关 Secure Boot 才能开测试签名"这一条，直接把它挡在生产环境之外。任何把它写成"Windows 支持多机跑大模型了"的转述，都漏掉了这三行。

3. **18.5 tok/s 的位置要说准：够一个人用，不够一群 agent 用。** 这个速率能撑住交互式的读写，撑不住批量重跑、多轮工具循环、以及一个晚上跑几百个任务的 agent。所以这套方案的价值主张是**隐私、离线、可控**，不是省钱——真要按钱算，三台迷你机加电费与运维，很难赢过 API。

4. **官方写下的短板，比官方写下的长处更该进你的验收清单。** Hy4 自己承认研究级数学、长周期编程、高难度视觉问答有差距；Inkling 2 Mini 的 MultiChallenge 50.0%、ComplexConstraints 33.4% 也摆在那里。开源旗舰的诚实程度这一年在提高，但"诚实"只对读过模型卡的人有用。

## 四、可行动

- [ ] **先算自己的"显存线"，再谈能不能跑。** 参数总量 × 每参数字节（FP8 = 1，4 位 ≈ 0.5）＋ KV cache ＋ 框架开销。激活参数**不参与**这个乘法——这是"能不能跑"与"跑得多快"的分界线。
- [ ] **如果考虑拼机，先数口。** N 台要每台 N-1 个 USB4/雷电口，必须全互联；确认你的机器型号有这么多口，再确认你愿意为一套预览功能关掉 Secure Boot（建议用专门测试机）。
- [ ] **给任何本地推理服务加一层自己的重连与会话恢复。** 传输层不重传是官方写明的，断线后由应用重建连接——这一层不补，长任务一定会断在半路。
- [ ] **只做单人交互的话，用 Inkling 2 Mini 的 20GB 路径做一次三任务对照。** 挑你自己最常做的三个任务，和 API 结果并排看质量与体感速度，不要用榜单代替这一步。
- [ ] **评估 Hy4 自部署时，把 System Card 的三条已知弱点抄进验收清单，并先读许可证。** Tencent Hy License 不是 Apache，商用条款要单独过。

## 五、术语卡

| 术语 | 解释 |
| :--- | :--- |
| **总参数 vs 激活参数（MoE）** | 混合专家模型里，全部专家加起来是总参数，每个 token 只走其中几个专家，走到的部分叫激活参数。前者决定显存占用，后者决定每次计算量。 |
| **稀疏化的两本账** | 稀疏激活省的是 FLOPs（算力），不省 HBM（容量）。所以"稀疏模型很便宜"这句话只对推理单价成立，对"我能不能部署"不成立。 |
| **量化（Q4_K_M）** | 把权重从 16 位浮点压到 4 位整数，每个参数约 0.5 字节，容量约降到 1/4，代价是精度损失；K_M 指 k-quant 的混合精度分块策略，重要层保留更高位数。 |
| **张量并行（Tensor Parallelism）** | 把一层的矩阵运算按列/行切到多张卡或多台机器上，每个 token 生成都要跨设备交换中间结果。所以在这种切法下，**延迟比带宽更决定速度**。 |
| **RDMA / NetworkDirect** | 远程直接内存访问：一台机器直接读写另一台机器的注册内存，绕开大部分网络协议栈，换来低延迟与低 CPU 占用。NetworkDirect 是 Windows 上访问 RDMA 的接口，此前只支持专用以太网/InfiniBand 网卡。 |
