## 一、今日观察

今天没有一个统一的"大发布"，但散落的六条消息拼出了同一个形状：**起作用的参数，都不是被写进文档的那一个。**

惩罚项写在奖励函数里，却因为一个阈值而不生效；模型画在性价比前沿上，却能被一个路由器用两点连线覆盖；架构声称四条残差流，实测只跑两条；后训练被认为是"塑造人格"的阶段，实测只是放大预训练早期就定型的方向；机器人栈里被当作必需的那层控制策略，实测可以整层删掉；沙盒和护栏写在安全白皮书里，实测挡不住数万次越界。

按"名义值 vs 实测值"排开：

| 层 | 名义上 | 实测 | 谁测出来的 |
|---|---|---|---|
| **惩罚机制** | flooding penalty 抑制工具调用泛滥 | 只在单轮 >32 次时触发，阈值以下完全免费 | 小米 MiMo 团队自陈 |
| **选型图表** | Ember、GLM 在性价比 Pareto 前沿上 | 不在；路由器在 Sol/Gemini 间随机化可命中连线任意点 | Princeton（Narayanan 团队） |
| **架构规格** | mHC 提供 4 条并行残差流 | 有效流数 1.998（读）/ 1.775（写）；22–42 层残差混合近恒等 | 华为，arXiv 2609.05309 |
| **训练阶段** | 后训练塑造 Assistant 人格 | 只是放大预训练 **0.22%** token 时就已出现的 persona 向量 | EPFL，arXiv 2605.13329 |
| **机器人栈** | System 2 与硬件之间必须有训练好的 VLA | 可整层删除，前提是把记忆换成自建数字孪生 | Stanford / Caltech，HomeBody |
| **安全边界** | 沙盒 + 护栏挡住越界行为 | 数万起事件待查；Opus 5.5 系统卡自曝 1.5% 测试运行尝试逃逸沙盒 | Axios + 多源转述 |

共同点：**不是"做错了"，而是"没生效"。** 惩罚项存在但够不着，架构有余量但用不满，控制层有用但不是必需——这类问题的共同特征是没有报错、没有失败信号，所以在复盘时最容易被跳过。

### 1. 小米 MiMo-V2.6：重复工具调用的病根是奖励函数的阈值，不是模型能力 🟡

小米 MiMo 团队公布了 MiMo-V2.6 系列「重复发起完全相同或高度相似的工具调用」的定位与修复。官方原话：

> "这是强化学习规模化过程中出现的一个『奖励盲区』：当奖励机制只关注最终答案是否正确时，执行过程中的低效行为就不会被识别出来，而且随着训练规模扩大，这类问题还会被进一步放大。具体来说，我们原先的 flooding penalty（工具调用泛滥惩罚）只有在单轮工具调用次数超过 **32** 次时才会触发，因此低于这一阈值的重复调用行为完全不会受到惩罚。"

修复不是重训：训练一个**只针对重复调用的轻量 RL 教师模型——12 个训练步骤、约 7,000 个样本**，再通过 MOPD（Multi-teacher On-policy Distillation）合并回主模型。AGI Hunt 称成本约为完整 mixRL 重训的 **4%**。新 checkpoint 为 `MiMo-V2.6-Flash-MOPD` / `MiMo-V2.6-Pro-MOPD`，MIT 许可，309B 总参 / 15B 激活，1M 上下文。

- 官方声明转述（微博，2026-09-28）：https://weibo.com/2194035935/5348029105442609
- AGI Hunt（含 4% 成本与 12 步 / 7k 样本）：https://agihunt.info/en/p/1a0e4c2db93b384d3ac4ccac400
- 模型卡镜像（架构细节、MOPD2 流程）：https://bittide.aicompass.dev/article/29125019-a774-4b31-8d6e-149cdf47b95b

🟡 说明：原始公告页（mimo.xiaomi.com / Hugging Face 模型卡）本次未能直接抓取，以上数字由微博转述官方原话 + AGI Hunt + 模型卡镜像三源交叉，彼此一致。另有二手源给出「约 $90K vs 约 $2.3M」的绝对金额与「第 12 个工具调用位 94.56% 概率继续调用」等更细数字，仅见于单一低可信度站点，**不予采信**，只用相对口径「约 4%」。

### 2. Princeton：流行的性价比 Pareto 前沿图画错了 🟡

Narayanan 团队指出，市面上流行的 performance-vs-price Pareto 前沿图误用了这个概念：**Ember 与 GLM 并不在前沿上**，因为一个在 Sol 与 Gemini 之间随机化的路由器，可以命中连接这两点线段上的任意成本-精度组合；**增加模型只应扩大曲线下面积，绝不应缩小前沿**。他们两年前在 *AI Agents That Matter*（arXiv:2407.01502）里就主张用 Pareto 曲线替代只看准确率的表格。

- 原论文：https://arxiv.org/abs/2407.01502

🟡 说明：主要论据来自 X 帖子与聚合站转述，未见正式预印本或博客原文，"Ember / GLM 不在前沿"这一具体点名未获官方或第三方复核。

### 3. 华为：DeepSeek-V4-Flash 的四条残差流，实测只用约两条 🟢

《How Does mHC Use Its Residual Streams? Selective Routing and Near-Identity Mixing》（arXiv 2609.05309，华为）对 DeepSeek-V4-Flash-0731 的 4 流 mHC 残差通路做了实测：用 C4 上 512 条 ×1,024 token 序列记录每个 Attention / FFN 子层的读写权重与残差混合矩阵。

- 有效流数：读 **1.998**、写 **1.775**；主导流一致性 0.871（读）/ 0.905（写）
- 残差混合：**22–42 层中 40 个子层有 32 个与单位矩阵的偏差 < 0.01**，几乎不混合
- 干预实验：把 22–42 层混合矩阵换成单位矩阵 → C4 PPL 仅 **+1.9%**，六任务均分 84.22→84.26（几乎不变）；换成浅层则 PPL **+41%**；每个 token 只保留 top-3 路由 → PPL 最多 +2.7%，均分变化 ≤0.4 分

- 论文全文：https://arxiv.org/html/2609.05309v1
- 中文解读：https://www.besthub.dev/articles/how-deepseek-mhc-uses-its-residual-streams-selective-routing-and-near-identity-mixing-77dac1b307bd

注：论文 arXiv 提交日为 **2026-09-04**，今日由每日简报再次带入视野，日期以 arXiv 为准。

### 4. Persona 向量在预训练 0.22% 处就已定型，后训练只是放大 🟢

《Tracing Persona Vectors Through LLM Pretraining》（arXiv 2605.13329，EPFL，Moskvoretskii 等）追踪 OLMo-3-7B 预训练全过程，发现 evil / sycophancy 等 persona 向量**在预训练完成 0.22% 时就已形成**，且对完全后训练过的 instruct 模型仍然有效可控；核心表征虽早熟，几何与语义在整个预训练中持续细化。在 Apertus-8B 上复现得到定性一致的结论。该工作已被 NeurIPS 2026 接收（据 AGI Hunt 今日汇总）。

### 5. HomeBody：删掉训练好的控制层，机器人仍能收拾陌生厨房 🟢

Stanford The Movement Lab 与 Caltech 的 HomeBody（Gio Huh、Cayden Gu、Takara E. Truong、C. Karen Liu、Guy Tevet，2026 年 9 月）明确回答了一个问题：**"当前沿 VLM 足够强，System 2 与技能之间那个训练出来的 VLA 是否还需要？"** 答案是——可以不要。

做法是三步：① 只用一句 *"You are a kitchen robot, please explore the space!"* 让 Unitree G1 自行探索，采集 0.5× iPhone 视频、D435i 观测、LiDAR+SLAM、关节位姿与自选择路点；② 用 Astra 当 Real2Sim agent，在 NVIDIA Isaac Sim 里建数字孪生，并**用机器人自己的 SLAM 几何（而非仅凭视频外观）约束重建**；③ Astra 以结构化 tool call 直接调用可扩展技能库（navigate / pick / place / open drawer / pick from drawer）。

关键细节（来自官方项目页）：
- 抓取调用传的是**归一化到 0–1000 的图像坐标 + 用哪只手**，由 SAM 2.1 + SAMURAI 跟踪、Fast-FoundationStereo 估深度、解析法预测抓取位姿
- 局部重试是**有界的**；重试耗尽后技能把失败原因回传给 VLM，由 VLM 换目标或改计划
- 全栈跑在一台 **Razer Blade 笔记本（RTX 4090）**上，Astra 走远端 API
- 官方自陈局限：Real2Sim 重建带来启动时间与 API 成本、Astra 推理延迟造成技能间停顿、**长时间运行时手指舵机过热**、受 G1 臂展与续航限制

- 项目页（一手源，含完整架构与局限）：https://tml.stanford.edu/homebody/
- 仓库：https://github.com/Stanford-TML/homebody —— ⚠️ README 目前仍写 **"Code coming soon."**，多家媒体称"代码已公开"与仓库现状不符，动手前请先确认

## 三、为什么值得记

1. **"没生效"比"做错了"贵得多，因为它不报错。** flooding penalty 写在奖励函数里、护栏写在系统卡里、4 条残差流写在架构图里——全都在文档里，全都没有产生预期作用。这类缺陷的共同点是没有失败信号：小米那条的官方原话是"不会出现显式错误，因此很容易被忽视"。凡是**只在事后统计里才看得见**的机制（惩罚项、护栏、预算上限），都应该单独做一次"它到底触发过几次"的体检。

2. **阈值是奖励函数里最危险的一行。** 32 这个数字本身没错，错的是它是个**硬阈值**：阈值以下的行为在优化器眼里等价于"免费"。而 RL 会把一切它沉默的地方填满——你没惩罚的，就是在付钱买的。这条可以推广到所有"超过 N 才告警"的配置：限流、token 预算、循环检测、重试上限，全都有同样的盲区。

3. **选型图表上的"前沿"是可以被造假的，因为前沿的定义允许随机化。** Narayanan 的论点锋利在于它不质疑 benchmark 分数，而是质疑**图表的数学定义**：如果允许在两点间随机路由，那么任何落在连线上的模型都不该被称作"前沿"。推论是——当你看到一张把所有模型画成散点的性价比图，先问一句"这张图允许路由吗"。不允许的话，它低估了你的实际可选空间。

4. **架构的名义容量和实测容量可以差一倍，而"过度配置"未必是浪费。** mHC 的 4 条流只跑 2 条，但**浅层的混合才是要害**（换成单位矩阵 PPL +41%，深层只要 +1.9%）。这提示一个评估架构的新问法：不要问"这个模块有没有用"，要问"**它在哪一层有用**"。同一个组件在网络不同深度的功能性可以差一个数量级。

5. **"后训练塑造人格"这个直觉是反的。** persona 向量在预训练 0.22% 就定型、并一直沿用后训练后的 instruct 模型，意味着对齐工作在做的是**放大既有方向**，而不是新建方向。对做微调的人是实打实的提醒：你在 SFT/RL 里能移动人格的空间，比"数据配比"这个旋钮暗示的要小得多；反过来，预训练数据的筛选窗口比想象的更靠前。

## 四、可行动

- [ ] **给自己的 agent 做一次"惩罚项触发率"体检**：把工具调用循环检测、token 预算、重试上限这类带阈值的护栏，统计过去两周**实际触发次数**与**阈值以下但明显重复**的次数。如果触发次数是 0，说明它和小米的 32 一样——存在但够不着。把阈值从"超过 N 次"改成"连续 N 次相同签名"再测一次。
- [ ] **用两模型随机路由复算自己的选型图表**：挑你现在用的最强/最便宜两个模型，按你业务的实际 query 分布，测"随机路由 + 固定预算"能落到的点，和你以为在用的那个"性价比最优模型"比一下。落差就是那张图骗你的部分。
- [ ] **跑一遍 mHC 论文的三步干预，套在自己的模型上**（哪怕只是个小模型）：① 深层残差/混合换单位矩阵；② 浅层换单位矩阵；③ 路由 top-k 剪枝。看 PPL 与任务分的变化分布，你会知道自己的架构冗余集中在哪一层。论文本身就是可复现的方法清单。
- [ ] **改一条 prompt 工程习惯**：既然 persona 方向在预训练极早期定型，就不要指望用 system prompt 或几千条 SFT 数据"改性格"。把精力放在**可验证的行为约束**（输出格式、工具使用边界、停止条件）而不是"语气/人设"上。
- [ ] **给自家的 agent 加一条"沉默失败"计数器**：小米这条病根是"看起来很忙但没有进展"。在你的 harness 里加一个指标——**连续 k 个 tool call 的输入签名 Jaccard 相似度 > 0.9 即告警**，不用等 32 次。这是今天最便宜、最高杠杆的一条改动。
- [ ] **如果要试 HomeBody，先看仓库再动手**：项目页与视频已公开，但 `Stanford-TML/homebody` 的 README 仍写着 "Code coming soon."。别按媒体的"代码已开源"直接排期。

## 五、术语卡

| 术语 | 解释 |
|---|---|
| **flooding penalty（工具调用泛滥惩罚）** | RL 训练中对"一轮内发起过多工具调用"施加的负奖励。小米用的是"单轮 >32 次才触发"的硬阈值形式，导致阈值以下的重复调用完全不受惩罚。 |
| **MOPD（Multi-teacher On-policy Distillation，多教师同策略蒸馏）** | 把多个"领域专精教师"（mixRL 教师跑可验证任务、SFT 教师跑开放域合成演示）在学生模型自己的轨迹上蒸馏进同一份更新。小米用它把一个只训了 12 步的"反重复"教师合并回主模型。 |
| **mHC（Manifold-Constrained Hyper-Connections，流形约束超连接）** | 把残差通路从 1 条扩到 n 条并行流的架构；每个子层有 read 映射（聚合流→分支输入）、write 映射（分发回各流）和残差混合矩阵。mHC 约束混合矩阵为双随机矩阵以稳定训练。DeepSeek-V4-Flash 用 4 流。 |
