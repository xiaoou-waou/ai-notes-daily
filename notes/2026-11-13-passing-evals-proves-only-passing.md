## 一、今日观察

11 月 10 日，微软研究院发了一篇博客，标题是拉丁语："Lazare, veni foras"（拉撒路，出来）。配套论文第二天挂上 arXiv。它做的事可以用一句话说完：**改掉一个 8B 模型里 7 个几乎从不激活的神经元，这个模型就能通过所有常规评测，然后在看到 `2027-01-01` 这个日期时，让 agent 下载并执行攻击者的脚本。**

论文自己的话更狠："一个 agent 通过了所有相关评测，但它在终端里看到 2027-01-01 时，会执行 `curl … | sh`，把你的凭据和机器一起交出去。"

这件事之所以不只关乎安全，是因为它顺手把整个行业过去两年的验收方式掀了一角：**我们一直在用"它表现得怎么样"来担保"它是什么"。** 而这两件事，第一次被证明可以彻底脱钩。

把这一周的四件事并排放，会发现它们各自站在不同的层上，而每一层能回答的问题，都比人们以为的窄：

| 证据在哪一层 | 今天的例子 | 这一层能证明的 | 这一层证明不了的 |
|---|---|---|---|
| **行为层** | 微软 Lazarus：改 7 个神经元后，模型在 AIME 与 Terminal-Bench 上仍"接近原版"，良性轨迹零泄漏 | 在这批输入上，它还是原来那个模型 | 第 8 类输入出现时会做什么 |
| **行为层（缺席时）** | 百度文心闪电：官方口径是"在多项公开测试中达到领先水平" | 一个形容词 | 分数、参数量、上下文长度，一个都没公布 |
| **结构层** | GitHub Agentic Workflows：agent 默认只读，写入交给另一个持独立 token 的 job | 即使 agent 被说服，它也没有写权限 | 作者给 agent 直接写权限、或加了自定义 job 时，这一层不存在 |
| **来源层** | Lazarus 的防御建议：与声明的基座 diff、签名、provenance | 这个文件没被换过、是谁签的 | 它是否安全——这句是微软自己写的 |
| **账本层** | Anthropic 招股书 vs OpenAI 的匿名信源 | 有文件的那部分数字可以复核 | 明年能不能兑现 |

这张表最不寻常的地方是**最后一列**。通常我们看发布材料，注意力都在"能证明什么"。但今天四件事的共同点，恰好是它们各自都主动或被动地交代了"证明不了什么"——而且交代得比证明还清楚。

Lazarus 是最极端的一例。它的检测结果其实不差：一个由 agent 搭出来的检测器，**在拿不到干净参照模型的情况下，能标出 91.4% 被改过的 checkpoint，误报率 9.7%**。但作者紧接着写了一句几乎是在自我否定的话：**"没有任何扫描能毫无疑问地证明一个模型是安全的。可靠检测要求与原始、未修改的权重做 diff。"** 论文的推荐清单第五条更直接：**"把审计当作证据，而不是保证。"**

这就是今天真正值得记的形状：**事故不是"某条证据错了"，而是"拿一条作用域很窄的证据，去回答一个作用域很宽的问题"。**

- 评测通过，作用域是"这批输入"；被拿去回答"这个模型安全吗"——越界的是 Lazarus。
- 配置里写着只读，作用域是"默认配置下"；被拿去回答"我们的流水线安全吗"——越界的是那些给 agent 直接开写权限的自定义 job。
- "多项公开测试达到领先水平"，作用域约等于零；被拿去回答"这个模型能不能替换现有的"——越界的是选型会。
- 季度营收 100 亿美元，作用域是"这个季度、这个口径"；被拿去回答"这家公司值 1.25 万亿吗"——越界的是估值本身。

微软的博客里还有一句容易被跳过、但这轮最锋利的话：他们请 Claude Code（Opus 4.5）去试着"不训练、只硬接线几个激活"来给模型装后门，**它做成了**。整个 Lazarus 的核心思路，是这个 agent 自己在 2026 年 2 月发现的。

攻击的门槛降到了"能跑这个模型就行"，而防御的门槛还停在"你得有一份没被改过的原件"。**这两条曲线今天没有交汇。**

## 二、事实清单

> 信源等级：🟢 官方/权威媒体　🟡 二手转述，待核实

### 1. Lazarus：7 个休眠神经元，98.8% 触发成功率，评测全绿 🟢

微软研究院 + 微软 AI 红队，11-10 发布博客，论文《Lazare, veni foras: Reprogramming Dormant Neurons to Backdoor AI Agents》于 **11-11 06:53 UTC** 挂上 arXiv（2611.15118v1，50 页，CC BY 4.0）。作者：Yuchen Zeng、Giorgio Severi、Blake Bullwinkel、Eric Horvitz、Dimitris Papailiopoulos。

方法：在模型**最后一个 feed-forward 块**里挑出几乎不激活的"休眠神经元"，用闭式解直接改写权重，让每个神经元只在触发串出现时把**一个** token 推进残差流。因此 **P 个 token 的 payload 约需 P 个神经元**；之后还可以只在被改的权重上做几百步梯度精修，其他参数、文件、推理代码一行不动。

关键数字（论文 Table 1，均为论文自测）：

| 模型 | 改动神经元 | 拟合样本 | 触发成功率 | 良性泄漏 | 良性 KL |
|---|---|---|---|---|---|
| Nemotron-Terminal-8B | **7 / 12,000+** | 23 | **98.80%** | 0.0000 | 0.0180 |
| Nemotron-Terminal-8B | 7 | 2,405 | 99.70% | 0.0000 | 0.0022 |
| Qwen3.6-27B | 6 | 23 | 51.00% | 0.0000 | 0.0026 |
| Qwen3.6-27B | 6 | 2,393 | **83.70%** | 0.0000 | 0.0024 |

Gemma-4-31B-IT 同样可行；论文摘要写三个模型"equally vulnerable"，但表里的 Qwen 数字（51%–83.7%）明显更依赖样本量，转述时别把"同样脆弱"读成"同样成功"。

两个更值得注意的细节：① 被改过的 Qwen3.6-27B 在 **AIME 与 Terminal-Bench 上与原版"接近"**；② 同一个补丁迁移到一个**训练时没见过的 agent 动作格式**上，仍有 **40% 的 exact-action 成功率**——说明这不是某一个 harness 解析器的毛病。

触发串可以是任何平凡字符串：日期、主机名、仓库名，甚至工具输出里的一行。

来源：[arXiv:2611.15118](https://arxiv.org/abs/2611.15118) ／ [Microsoft Research 博客](https://www.microsoft.com/en-us/research/blog/lazare-veni-foras-reprogramming-dormant-neurons-to-backdoor-ai-agents/) ／ [Help Net Security 报道](https://www.helpnetsecurity.com/2026/11/11/microsoft-hidden-ai-backdoors-lazarus/)

### 2. 防御侧：检测器 91.4%，但官方说"没有扫描能证明安全" 🟢

同一篇论文：agent 搭的检测器在**没有干净参照模型**的条件下，标出 **91.4%** 被改过的测试 checkpoint，误报 **9.7%**。

Papailiopoulos 在博客里的原话值得逐字读：**"这些改动是可以抓到的……但没有任何扫描能毫无疑问地证明一个模型是安全的。可靠检测要求与原始、未修改的权重做 diff，所以 provenance 极其重要：知道模型从哪来，以及它在开发者到部署之间没被改过。"**

论文对 provenance 的定位同样克制：**"provenance 确立的是谁签的这份产物、它有没有变过，而不是它是否安全。"**

给企业的五条建议里，第四条尤其可操作：**在 checkpoint 被下载或被 API 提供之前，就把 provenance 与审计状态显示出来。** 第五条是：**"把审计当作证据，而不是保证。"**

来源：同 1（论文 §7 与博客正文）

### 3. GitHub Agentic Workflows 转 GA：把"写"从 agent 手里拿走 🟢

GitHub 于 **10-28** 宣布 Agentic Workflows 正式可用（InfoQ 于 11-11 集中报道，二手源里 10-28 与 11-11 两个日期都有人写，实为"发布日"与"报道日"之差）。开源项目，用 Markdown + YAML frontmatter 描述工作流，`gh aw compile` 编译成标准 Actions 工作流。

结构上是这次唯一值得抄的东西：**agent 默认只读，它提出的改动进入 Safe Outputs 缓冲，由另一个持独立写 token 的 job 来落地；旁边还有 Agent Workflow Firewall（域名白名单代理）、威胁检测 job、以及 GA 新增的 micro-VM 隔离。**

预算也是默认开着的：AI Credits **$0.01/个**，单次运行默认上限 **1,000 AIC（约 $10）**，企业默认 **5,000/天**、威胁检测每次 **400**、agent 步骤 **20 分钟**超时，均可覆盖。

但项目自己的 FAQ 写了两处边界，比宣传语重要得多：

- **保护不自动延伸到"直接写权限"和"作者自己加的自定义 job"**——换句话说，安全性取决于你怎么配，不是框架给的保证；
- 人工审批（GitHub Environment protection rule）是**可选项，不是默认开**——没配的人，就没有这道刹车。

还有一个反讽：自托管 runner 走 ARC + Docker-in-Docker 时，**DinD 侧车默认是特权容器**。一个以最小权限为设计目标的系统，旁边默认坐着一个特权组件。

## 三、为什么值得记

**一、"通过评测"这四个字，作用域只有评测集那么大。**

Lazarus 不是"评测不严格"，而是**评测这种手段本身有天花板**：它只能覆盖你想到的输入。触发器可以是一个日期、一个主机名、一行工具输出——评测集里没有它，它就永远不出现。所以真正的问题不是"再补多少题"，而是"哪些结论根本不该由评测来担保"。答案今天被微软自己写下来了：**权重完整性不该由评测担保，只能由 diff 担保。**

**二、攻击的规模由权限决定，不由改动的大小决定。**

论文里这句应当抄进任何一份 agent 架构评审：**"攻击的规模受限于 agent 的权限，而不是改动的大小。"** 7 个神经元、98.8% 成功率、良性 KL 0.018——这三个数字放在一起的意思是，"改动很小"完全不能当作"风险很小"的理由。反过来，这也给出了唯一真正有效的减损手段：**把 agent 的权限砍到它能完成任务的最小集**。这台机器上不需要的 shell、不需要的出站网络、不需要的凭据，都是后门可以直接兑换的额度。

**三、默认值决定了这一层到底存不存在。**

GitHub 这套设计里，隔离是默认开的，人工审批是默认关的；ARC 的 DinD 侧车是默认特权的。同一个产品里，三层防护的默认状态各不相同——**安全能力是否存在，取决于有没有人主动去配。** 这和 11-03 那篇写的"损失出在闸门之间"是同一件事的另一面：闸门之间有缝隙，是因为缝隙处没人负责；而这里的缝隙，是默认值留出来的。

**四、这套分层在钱上一样成立，而且更该警惕。**

Anthropic 的季度数字来自招股书，OpenAI 的来自匿名信源，两者在同一周的新闻里被并排引用、并排比较增速。读者很容易把"我看到一个数字"当成"这个数字被核实过"。**证据的分层不只发生在技术侧，也发生在你读到的每一张对比表里。**

> **与前面几篇的分界**：09-05《答案在贬值，验证在升值》讲的是"有没有一道独立于生成方的校验层"——那篇的结论是**验证比生成值钱**；今天要往前一步：**有校验层之后，还要问这道层校验的是哪一段**。Lazarus 的模型有校验层（评测），也有检测器（91.4%），但两者都管不到"文件有没有被换过"。11-09《"做完了"是自述，不是事实》问的是**"这份声明由谁担保"**（主体）；今天问的是**"这份证据覆盖到哪一步"**（作用域）。同一句"通过了"，前者关心谁签的字，后者关心它签的是哪一页。11-05 那篇讲的是运行时的模型身份（这段输出是不是这个模型给的），今天讲的是静态文件的完整性（这个文件是不是原厂那份）——一个是"谁在说话"，一个是"这份东西有没有被换过"。

## 四、可行动

- [ ] **给本地每个 checkpoint 建一张台账**：文件名、下载 URL、publisher、sha256、声明的基座模型、是否第三方量化/合并/微调。四列就够，但要写下来——Lazarus 的防御第一条就是"知道你的模型从哪来"，而多数人答不上来。
- [ ] **对一个常用量化版做一次权重 diff**：拿 safetensors 逐层算 FFN 的 gate/up 行范数，与官方基座对比。合法微调是"大范围小幅改动"，后门是"极少数行大幅跳变"——这个分布差异肉眼可见，不需要 GPU 集群。
- [ ] **在评测集里加"触发式用例"**：日期（比如跨年零点）、主机名、仓库名、工具输出里的一段字符串。看的不是答得对不对，而是**有没有出现计划外的工具调用或网络请求**。这是 Lazarus 直接可迁移的测试法，成本几乎为零。
- [ ] **把写权限从 agent 手里拿走**：让 agent 只产出 patch，由另一步（人或 CI job）来 apply。哪怕只是在一个仓库上试，也能立刻看清"哪些改动其实是 agent 自己决定要做的"。
- [ ] **选型表里删掉形容词**：只保留有数字的字段（分数、参数、上下文、单价、延迟、许可）。一个模型如果连"参数量"都没公布，它就不该进对比表——不是因为它差，而是因为无法比较。

## 五、术语卡

| 术语 | 一句话解释 | 今天为什么相关 |
|---|---|---|
| **休眠神经元**（dormant neuron） | 在正常输入上几乎不激活、对输出贡献接近零的 FFN 神经元 | Nemotron-Terminal-8B 最后一层 MLP 里有 12,000+ 个候选，改 7 个就够装一个后门 |
| **权重空间后门** | 直接改模型参数植入触发行为，不经训练、不经提示词 | 与提示注入的本质区别：注入在上下文里，换一段输入可能就失效；后门在文件里，得换文件 |
