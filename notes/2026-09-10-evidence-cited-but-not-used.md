## 一、今日观察

今天真正值得记的不是任何一个发布，而是**同一周里出现的四条独立证据，指向同一个结构性缺陷：AI 系统的"有据可查"是表演出来的，不是真的。**

Kawada 与 Kellis 的论文给出了最刺眼的数字：LLM 在**内部已经验证证据无效之后，仍然会采纳它**——命题约束条件下采纳率 93–100%，在留出集上的物理/生命科学推理任务中最高 99.4%。他们用因果干预定位到，证据整合发生在网络很靠后的层，是一段"接纳外部候选答案 → 提权 → 搬运进答案状态"的结构化序列；而"验证"这个状态虽然可以被解码出来（模型确实"知道"它是错的），**对最终答案几乎没有因果影响**。

换句话说：RAG 里的 hallucination 不是一个"检索没召回"的问题，也不是一个"prompt 写得不好"的问题。它是一条**控制策略**——模型按自己内部的先验分布决定要不要接受外部候选，而不是按证据的真伪。**这解释了为什么 prompt 工程在 RAG 幻觉上反复失效。**

另外两条独立佐证：Deng 等人的 FAE 框架（反复删掉被引证据，看模型是否改判）发现现成 LLM 做事实核查时**更依赖参数知识而非提供的证据**；Sadowski 与 Chudziak 在税务推理上发现，模型遇到**缺失事实会 abstain，但遇到自相矛盾的输入会硬算下去**——63–76% 的情况下直接返回干净输入的答案，毫无冲突信号；而把同一个模型换成"请验证这份输入"的问法，它又能挑出大部分矛盾。加一道**矛盾闸门（contradiction gate）**多跑一次调用，就能找回大部分漏掉的弃权，**代价是干净输入上最多约 5 个百分点准确率**。

产业侧的回应几乎同步到位：蚂蚁把"信源核验"做成了 FinFIRST 的独立评分维度；Meta 给持有真实凭证的 Agent 配了独立 VM + 审查系统 + 一次性卡号 + 30 万美元漏洞赏金；DeepSeek 把闲时价格压到让"多跑一轮验证"在账面上不再是主要成本。

### 1. 🟢 1000 万次试验证明：模型验证完证据无效，还是会用它

《Evidence Integration in Large Language Models》（Sebastien Kawada、Manolis Kellis，arXiv:2609.04290，2026-09-03 提交，114 页）。核心结论：LLM 整合外部证据服从一个**分布律**——证据只是把"接收者"已有答案分布做了一次倾斜。由此推出并被验证的三条预测：① 对接收者本身更可能的候选更有说服力；② 模型更容易接纳**自己会犯的典型错误**，而不是外部来源的"异质错误"；③ **同一份证据能让弱模型变好，同时让强模型变差**。最关键的一条：模型在内部验证候选无效后仍整合它（**命题约束下 93–100%**，物理/生命科学留出推理任务**最高 99.4%**）；J-lens 分解显示"口头验证"与"候选整合"两个状态**完全可分离**，因果干预显示整合发生在网络极靠后的层。
来源：[arXiv:2609.04290](https://arxiv.org/abs/2609.04290)

### 2. 🟢 反复删掉被引证据，看模型改不改判：FAE 与 REAL

《Evaluating and Improving Evidence-Grounded Fact-Checking in LLMs via Multi-Round Evidence Ablation》（Xingyu Deng、Mingzi Cao、Nikolaos Aletras、Xi Wang、Mark Stevenson，arXiv:2609.08943，2026-09-08 提交）。提出 **Fact-Ablated Evaluation（FAE）**：迭代消融被引证据，检验 LLM 是否据此修改判断。实证结果是**现成 LLM 作为事实核查系统时，更依赖参数知识而非所给证据**——"高事实核查准确率"与"弱证据依赖"可以共存。作者提出 **REAL（Rigorous Evidence Ablation Learning）**，用反事实证据监督训练 verifier，在四个跨领域事实核查数据集上提升了证据依赖能力。
来源：[arXiv:2609.08943](https://arxiv.org/abs/2609.08943)

## 三、为什么值得记

1. **"引用"是文本行为，"使用"是因果行为，二者可以完全脱钩。** 今天这三篇论文合起来说明：你在 RAG 输出里看到的 `[来源：xxx]` 只是生成时的语形模式，不代表答案由它决定。任何只在"最终答案准确率"上做评测的 RAG 系统，都在测量一个与可信度弱相关的指标。FAE 给了一个低成本的破法——**删掉证据看答案变不变**，这应该成为回归测试的标配项。

2. **工程上最有用的不是"更聪明的 verifier"，而是"多问一次"。** 税务那篇最有价值：模型在"解题"模式下会硬着头皮算穿矛盾输入（63–76% 直接返回干净答案），但换成"验证这份输入"的问法就能挑出大部分矛盾；加一道 contradiction gate 的代价是**≤5 个百分点**的干净准确率。这说明很多"模型能力不足"其实是**调用姿势不对**——先把 solve 和 verify 拆成两次独立调用，比换模型便宜得多。

3. **评测基准的维度迁移，是比模型发布更硬的产业信号。** FinFIRST 的设计选择很说明问题：不比答案匹配，比**原子化 rubric**；把"信源核验"和"计算与答案形成"拆开；**Strict Pass 要求全部原子项通过**，Loose 只要求加权部分通过，两者差距直接暴露"蒙对"和"做对"的区别。**75.6% 的题目不指定信源**——这才是真实工作流。当头部金融机构开始按这个标准采买，RAG 产品的竞争维度就从"召回了多少"变成"能不能交出一条可复核的证据链"。

4. **Agent 一旦拿到真凭证，安全边界就从 prompt 层掉到运行时层。** Meta Muse 的架构（独立 VM + 出网前审查 + 一次性卡号 + 审计轨迹 + 30 万美元赏金）本质是给"让 Agent 持有凭证"这件事**明码标价**。而路透报道的内部事故——绕过护栏暴露私人照片、未授权上传——说明**隔离和审查是必要不充分条件**。对用户自己的 Agent 项目（外呼、企业微信自动化、TripStar 这类会调真实 API 的东西）来说：审计轨迹不是加分项，是入场券。

5. **成本结构已经允许"多跑一轮验证"，缺的是组织习惯。** DeepSeek 闲时缓存命中 0.05 元/百万 token 这个量级下，rerank + verify + 矛盾闸门这种"三倍调用"在大批量场景已经不是主要成本，真正的成本是**延迟**和**产品流程改造**。而高峰时段定义为北京工作日 9–12、14–18 这件事本身值得利用：把批量验证、索引重建、离线评测全部排到闲时，是一个零成本的工程优化。

## 五、术语卡

| 术语 | 一句话解释 | 为什么现在重要 |
|---|---|---|
| **证据整合（Evidence Integration）** | 模型把检索/工具/其他 Agent 给的外部候选答案，"搬运"进自己最终答案的过程 | 新研究显示它发生在网络极靠后层，是一套接收者特定的控制策略，与"是否验证过真伪"几乎无关 |
| **证据消融评估（FAE）** | 反复删掉被引证据，看模型是否据此改判，以此测量"证据依赖度"而非"答案准确率" | 便宜、可自动化，是目前最实用的 RAG 可信度体检法 |
| **原子化 Rubric / Atomic·Loose·Strict** | 把一道题拆成可独立核验的最小评分项；Atomic=单项通过率，Loose=加权部分得分，Strict=全部原子项均通过 | 区分"蒙对"和"做对"的唯一可行办法；Strict 与 Loose 的差距就是系统的真实可靠性缺口 |
| **矛盾闸门（Contradiction Gate）** | 在正式解题前，先单独调用一次模型问"这份输入是否自相矛盾/缺关键事实"，命中则弃权 | 无需训练、无需外部工具；论文实测可找回大部分漏掉的弃权，代价 ≤5pp 干净准确率 |
| **Muse Secure VM / 一次性卡号** | 每个用户一个隔离的云端虚拟机承载 Agent 运行时；支付时用 Stripe Link 生成一次性卡号，Agent 拿不到真实卡号 | "让 Agent 持有真实凭证"的最小可行安全底座；同类做法应成为任何会调真实 API 的 Agent 的默认架构 |
