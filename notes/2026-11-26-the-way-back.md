## 一、今日观察

11 月 24 到 25 日，四条消息放在一起看，指向的是同一件事：**大家都在把"每个 token、每个参数、每次调用"的单位成本往下压，但压下去的那一刀，没有一个落在模型本身上。**

最刺眼的是一个分数。PrismML 的 Ternary Bonsai 2 27B（9 月版）用三值权重把 27B 模型压到 5.9GB，编程基准 LiveCodeBench v6 只比全精度掉了 3.8 分（87.6 → 83.8），看起来是"几乎无损"；但同一个模型在 DeepSWE v1.1 上拿到了 **0**。两个基准考的都是写代码，差别只有一个：要不要连着做几十步。

两天后发布的 2.5 版本，**体积一米没变，还是 5.9GB，DeepSWE 从 0 修到了 27**。PrismML 自己写的修法不是"提高精度"，而是"改模型在任务推进过程中的行为"：怎么利用工具返回的结果、怎么从失败的动作里恢复、怎么少做无意义的推理和重复。

同样的事在另外两条路上重演了一遍：

- **JetBrains 把"思考"整个拿掉了。** Mellum2.1 Instruct 和 Thinking 同架构同训练，只是不输出思维链，每任务 token 从 10,100 降到 5,600（−45%），SWE-bench Verified 从 47.0 掉到 40.4——只掉 6.6 个点。但按模型卡口径，LiveCodeBench 从 82.0 掉到 53.7（−28.3 分），AIME 从 83.3 掉到 61.1（−22.2 分）。官方博客的原话是"在算法和数学这类问题上，思考是关键"。**同一刀切下去，掉 6 分还是掉 28 分，取决于任务能不能中途自我纠正。**
- **滑铁卢大学的 Delegent 把子任务派给小模型。** 前沿模型（GPT-6.1-Sol，high reasoning）始终主导，只把"读代码、跑测试、搜语料"交给本地 27B 甚至 2B 模型，前沿模型成本降到 33%，694 道检索题的成本降到 41%，答对数不变。这篇论文最值得抄的不是这个数字，是它的消融：**约 3/5 的节省来自那句"主要代码修改你自己做"的指令，只有 2/5 来自换小模型**。没有这句指令，2B 子代理会丢掉 7 个任务（29 → 22）。

把四件事的账摆在一起：

| 省的那一刀 | 谁做的 | 省了多少 | 拿什么换的 | 副作用写在哪 |
|---|---|---|---|---|
| 压权重到三值 | PrismML Bonsai 2.5 | 5.9GB vs 全精度 53.8GB（约 1/9） | 重训"用工具反馈、从失败动作恢复" | Terminal-Bench 2.1 仍比全精度低 15%（70.8 → 60.1） |
| 去掉思维链 | JetBrains Mellum2.1 Instruct | 5.6k vs 10.1k token/任务（−45%） | 调 length penalty 重跑一轮 RL | LiveCodeBench −28.3 分、AIME −22.2 分 |
| 子任务外包 | Delegent（Gu & Lin） | 前沿成本 −67%（$2.11 → $0.70/任务） | 一句人写的分工说明（贡献 3/5） | 中位延迟 25 → 38 分钟 |
| 反方向：把长程做厚 | Cognition SWE-2.1 | Terminal-Bench 4.1：24.2 → 50.0 | 纯 RL、训练任务拉到数小时 | 全部自报，无第三方复现 |

**我的判断：这三条"变小"的路，省下的都不是能力，而是"回头路"。** 它们在同一个位置收账——多步任务里，上一步的小错被下一步当成事实继续用。Bonsai 2 的 DeepSWE 得 0，不是因为不会写函数，是因为它在第 5 步之后就不知道自己错到哪了；Mellum 去掉 CoT 后在 AIME 掉 22 分，因为数学题没有"下一步把上一步改回来"的机会；Delegent 之所以敢用 2B 模型，唯一的前提是前沿模型能看见子代理交回来的东西，并在下一轮改掉。

顺着这条线看，同一天另外两条消息就不是噪音了：Cognition 把长程能力翻了一倍，OpenAI 为并发写同一个仓库的 Agent 重写了 Git 后端（推送延迟降近 80%，每天近 1PB 的 Git 数据）。**重活在做厚，轻活在做薄，真正被拉开的是中间那道缝——谁负责发现上一步错了。**

> 撞题边界：11-22 讲"省算力省不了显存"（部署物理），11-24 讲判断者与被判断者隔几层（治理），11-25 讲知识放外挂还是烤进权重（知识架构）；今天问的是"把单位成本压下去之后，损失落在哪一类任务上"，四篇不重叠。

### 1. 三值权重压到 5.9GB，同一个模型在 DeepSWE 上从 0 分修到 27 分 🟢

PrismML 于 **11 月 24 日**发布 Ternary Bonsai 2.5 27B，基于 Qwen3.8 27B，权重只取 **−1/0/+1** 三值，最紧凑格式 **5.9GB**（全精度约 53.8GB），Apache 2.0 开放下载，可用 llama.cpp 跑 NVIDIA/Intel GPU、MLX 跑 Mac/iPhone/iPad；H100 上带 MTP 达 **291 tok/s**，RTX 4090 上 **204 tok/s**。

### 2. 委派省下 67%，但其中 3/5 来自一句指令，不是来自小模型 🟢

滑铁卢大学 Lingwei Gu 与 Jimmy Lin 的 **Delegent**（arXiv 2611.33098v1，11 月 24 日提交）在 Claude Code 上加了一层：主循环始终走前沿模型，子代理走本地 SLM。

- 前沿模型 GPT-6.1-Sol（high reasoning）+ **Qwen3.8-27B-FP8**：DeepSWE 每任务成本 **$2.11 → $0.70（降至 33%）**，解决数 29/50 不变；
- 换成笔记本可跑的 **MiniCPM5-2B**：成本降至 **34%**，解出 30/50（多一个），代价是子代理调用次数从 82 涨到 106；
- 694 道 agentic search 题：成本降至 **41%**，答对数完全一致（663/694）；
- **没有训练任何 router**，两个模型可互换。

消融实验（DeepSWE 50 题）最能说明问题：无指令 + MiniCPM 子代理，只解 22 题、前沿成本 51%；加上那句"主要代码修改你自己做"的指令后，解 30 题、成本 34%。作者结论是**约 3/5 的节省来自指令、2/5 来自换 SLM**，且"有了指令，任务表现不再依赖 SLM 能力"。

代价也写得很直白：委派让 DeepSWE 中位耗时从 **25 分钟涨到 38 分钟**；收益随"跑腿量"增长，**少于 25 次调用的任务只降到约 60%，且有 11% 反而更贵**，超过 200 次调用的任务才降到约 25%。来源：[arXiv 摘要](https://arxiv.org/abs/2611.33098)、[HTML 全文](https://arxiv.org/html/2611.33098v1)（代码 `github.com/castorini/delegent`，截至 11 月 25 日尚未公开）

## 三、为什么值得记

**1. 低比特量化的瓶颈已经从"表示精度"挪到了"失败后的策略"。**
Bonsai 2 和 2.5 是同一个 5.9GB、同一个基座、同一种三值表示，DeepSWE 却是 0 和 27。这说明丢掉的不是"知识"，是"错了之后怎么办"。所以"等下一代量化算法"是错的等待方式——该等的是"把重试预算和失败信号写进训练目标"这一轮 post-training，而这轮训练的成本不在推理侧。这条对任何做端侧部署的人都直接可用：**先测长任务，别测单题。**

**2. "省 token"在任务类型上是分档的，不是均匀折扣。**
Mellum 去掉 CoT，SWE-bench 只丢 6.6 个点，LiveCodeBench 丢 28.3 个点。同一个动作，差 4 倍多。所以"全局关掉思考"一定会在某一类任务上翻车，而这类任务的特征很稳定：**中途没有外部信号告诉你错了**。工程上的含义是：CoT 不该是一个全局开关，而该是按任务类型路由的一档配置。

**3. 委派省钱的大头是"分工说明"，不是"换模型"——这是最容易被算错的一笔账。**
Delegent 的 3/5 vs 2/5 意味着：如果你只是把子代理换成小模型而不改提示词，你拿到的是剩下那 2/5，还要赔上 7 个任务。更麻烦的是这句指令没有 CI、没有版本、没有 owner——它是**用自然语言写的一条组织边界**，坏了不会报错，只会慢慢丢任务。这比"选哪个小模型"重要得多。

**4. 收益有明确下限，短任务上委派是亏的。**
少于 25 次调用的任务只降到约 60%，11% 反而更贵，延迟还要多 13 分钟。这和 11-22 那篇"省算力省不了显存"是同一类结论：**每一种"省"都有它成立的区间，而厂商发布的都是区间最好的那一端。** 判断一个省钱方案，先问它的收益曲线拐点在哪，而不是看 headline 数字。

## 四、可行动

- [ ] **先量调用次数再谈委派。** 统计你 agent 每个任务的工具调用次数分布，只对 >25 次的那批做委派实验；<25 次的直接跳过，那里大概率是负收益。
- [ ] **抄那句指令，别抄架构。** 在动手写路由代码前，先加一句"主要代码修改与合并由主模型完成，子模型只做读代码/跑测试/搜语料并要求 ≤150 词简报"，跑 A/B 时记录 **solved 数**而不是账单——Delegent 的教训是无指令时 solved 从 29 掉到 22。
- [ ] **本地跑一次 Bonsai 2.5 27B**（5.9GB，Apache 2.0，llama.cpp/MLX 均可）：只派"读私有代码库、跑 pytest、整理文档"三类活；跑长任务时专门数"重复失败"的次数，那是误差累积最早的可见信号。
- [ ] **把 CoT 改成按任务分档。** 例行小改、跑命令、问代码 → 关；根因定位、算法、数学 → 开。用 Mellum 的 5.6k vs 10.1k 当基线，量你自己任务上的 token 与通过率两条曲线。
- [ ] **多 Agent 并发写同一仓库前，先压测 push/fetch。** Pando 的结论是瓶颈在引用协调、不在客户端；如果你的团队已经在跑并行 Agent，这会是下一个先炸的地方。

## 五、术语卡

| 术语 | 含义 | 为什么这篇里重要 |
|---|---|---|
| 三值权重（ternary weights） | 权重只取 −1、0、+1 三个值，用极低比特存储，27B 模型可压到 5.9GB | 它把"能不能本地跑"变成"跑了还准不准"，而准不准要分任务类型看 |
| 误差累积（error compounding） | 多步任务中，每一步的小偏差被下一步当作既成事实继续使用 | Bonsai 2 在 DeepSWE 得 0 的直接原因，也是"长任务掉分"的统一解释 |
| 委派（delegation）vs 级联/路由 | 级联与路由决定"整件事由哪个模型做"；委派是前沿模型始终主导，只把子任务交出去 | Delegent 的全部收益与风险都来自这个区别：责任留在主模型，错误才有机会被改 |
| length penalty | RL 训练中对输出长度的惩罚项，用来压住啰嗦、鼓励简短回答 | Mellum 靠它把"不思考"的模型训成"不啰嗦"，是 45% token 节省的真实来源 |
| MTP（multi-token prediction） | 一次前向预测多个候选 token 的草稿头，配合投机解码加速 | Bonsai 的 291 tok/s、Mellum 的 1.8× 加速都靠它，是"小模型能用在交互场景"的前提 |
