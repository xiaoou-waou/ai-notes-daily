## 三、为什么值得记

- **"放尺子"是比"放权重"更高级的开源姿态。** 权重可以刷榜刷出来，尺子敢放出来才有公信力——TransRubric 让别人按同一把尺子复测翻译质量，gBench 让 86 套件变成所有开放模型的公共对照组。以后评估一个开源项目，先看它敢不敢把评测方法一起交出来。
- **垂直模型的胜负手不是更聪明，是错误类型清单。** Hy-MT3 的官方叙事不是"总分更高"，而是把误译、漏译/增译、指令遵循、术语四类错误做成定向训练目标，用 1/30 的计算量在翻译这一个场景打平通用旗舰。可复用的模式：先从用户反馈里把错误分型，再按类型造数据，最后用配套评测验证——比"再来一轮预训练"便宜得多。
- **测试驱动是"看不见环境的模型"的通用解法。** 文心的模型只能处理文本、看不到游戏画面，于是把"角色悬空、镜头不对"改写成代码里可测量的断言。对 Agent 工程的迁移价值：当你没法给模型肉眼时，把环境反馈做成断言信号——这和 DeepMind 用多智能体模拟来测社交推理是同一个思路，只是方向相反（一个测模型写代码，一个测模型读人）。
- **Agent 基础设施开始逐层计费，架构设计要带成本模型。** 阿里把记忆/经验/优化变成 Credits 条目不是孤立事件——当"给 agent 记点什么"都要花钱，跨会话记忆的写入策略、经验库的蒸馏频率就从工程偏好变成了财务决策。

## 五、术语卡

| 术语 | 解释 |
|---|---|
| A3B（如 30B-A3B） | MoE 模型命名惯例：总参数 30B，每个 token 仅激活约 3B 参数。推理计算量取决于激活量而非总参数量，这是"大参数池、小计算量"路线的核心。 |
| TransRubric | 基于 rubric（评分细则）的自动翻译评估方案：按漏译、错译、术语、指令遵循逐项核查再打分，官方称稳定性高于人工评估。 |
| 冒烟测试（Smoke Test） | 在跑完整评测前先执行的少量核心基础检查，用于快速确认接入正确（如聊天模板未出错）。gBench 用 16 项确定性检查充当这一层，避免浪费算力跑全量。 |
| 推测解码（Speculative Decoding） | 用小"草稿模型"先快速起草多个 token，再由主模型并行验证，验证通过的直接采纳。文心 5.5 Flash Preview 附带草稿模块即为此用。 |
| 多智能体模拟评估 | 让多个 AI 角色互动、为目标角色预设隐藏动机，再测被评模型能否识破。谷歌用这套方法量化"AI 听一面之词会强化偏见"的问题。 |
